# Приложение для Android и канал a1

Приложение — админка прослойки в телефоне и уведомления о событиях. Репозиторий: https://github.com/Mrvibecodic/submw-android. Ставится из APK, обновления берёт у самой прослойки.

С прослойкой приложение общается по своему каналу **a1**. Он отдельный от канала c1 Clod Clash: свой путь, свой ключ прослойки, свой формат. Общее — только набор примитивов: **X25519 + HKDF-SHA256 + ChaCha20-Poly1305 (IETF, nonce 12 байт)**, base64url без `=`. Согласования алгоритмов нет.

Снаружи видны только `POST <адрес>/a1/<метка>/<отпечаток>` с телом-шумом и ответ `200` с телом-шумом, кратным 4096 символам.

---

## Как включить

1. Вкладка **Настройки → «Приложение»**, тумблер «Приложение».
2. «Добавить телефон» — прослойка покажет код вида `XXXX-XXXX-XXXX`. Он живёт 5 минут и срабатывает один раз.
3. В приложении: адрес прослойки и код. Потом — логин и пароль админки.

Дальше там же: список телефонов с отключением, смена ключа, режим «Админка только из приложения» и предел соединения уведомлений.

**Если телефон потерян**, а включён режим «только из приложения»: допишите `'app_only_off' => true,` в `config.php` или задайте `SUBMW_APP_ONLY_OFF=1` в Docker — браузер снова пустит в админку. Отключить телефон можно на той же вкладке, он теряет доступ сразу.

Нужен PHP с расширением `sodium`, как и для канала c1.

## Ключи

| Ключ | Где живёт | Что это |
|---|---|---|
| `S` | таблица `app_key` | статическая пара X25519 прослойки; при смене хранятся две последние |
| `D` | телефон, под ключом Android Keystore | статическая пара X25519 телефона, создаётся при добавлении |
| `did` | обе стороны | 16 случайных байт, выдаёт прослойка; в JSON — base64url |
| `k_dev` | вычисляется | `HKDF(ikm = X25519(D, S), salt = "submw-a1", info = "dev" ‖ did, 32)` |

`k_dev` знают только телефон и прослойка: он доказывает сразу и то, что пишет добавленный телефон, и то, что отвечает та самая прослойка. Подписей нет.

Отпечаток `spid` — первые 6 символов base64url от SHA-256 публичного `S`. Метка суток:

```
kid = b64url( HMAC-SHA256(k_dev, "kid|<unix / 86400>")[0..9] )      12 символов
```

Прослойка на каждый запрос перебирает добавленные телефоны и считает их метки на вчера, сегодня и завтра — индекса не нужно, телефонов единицы.

## Рамка

И в запросе, и в ответе внутри шифра лежит рамка — JSON и двоичное тело без перекодирования:

```
рамка = u32be(длина JSON) ‖ JSON ‖ u32be(длина тела) ‖ тело ‖ нули
```

Нули дописываются так, чтобы весь блок `эфемерный ключ(32) ‖ шифротекст ‖ тег(16)` был кратен:

- **512 байтам** — запрос, если без выравнивания он не больше 4096 байт;
- **3072 байтам** — большие запросы и все ответы (в base64url ответ — ровно 4096·N символов).

Размер запроса ограничивает `post_max_size` PHP и предел тела у веб-сервера: base64 на треть длиннее данных, поэтому при обычных 8 МБ проходит около 6 МБ тела.

## Добавление телефона

```
POST <адрес>/a1/0/0
тело  = b64url( eph_pub(32) ‖ AEAD(k_p, nonce 0, рамка, aad = "a1p" ‖ eph_pub) )
k_p   = HKDF(ikm = код, salt = "submw-a1-pair", info = "req" ‖ eph_pub)
JSON  = {"v":1,"t":…,"n":"<16 байт>","op":"pair","dpub":"<D_pub>","name":"<модель>","os":"android","osv":…,"app":"<версия>"}

ответ = b64url( S_eph(32) ‖ AEAD(k_pr, nonce 0, рамка, aad = "a1pr" ‖ eph_pub ‖ S_eph) )
k_pr  = HKDF(ikm = код ‖ X25519(S_eph, eph_pub), salt = "submw-a1-pair", info = "res" ‖ eph_pub)
JSON  = {"v":1,"t":…,"n":"<эхо>","st":200,"did":"…","sp":"<S_pub>"}
```

Код — 12 символов Crockford base32 (без I, L, O, U; при вводе I и L читаются как 1, O — как 0), около 60 бит. Прослойка пробует активные коды (их не больше трёх), удачный гасит. Неудачные попытки считаются по адресу: 20 за 15 минут — и адрес ждёт.

Пароль в добавлении не участвует. Посредник, который видит TLS насквозь, за 5 минут код не подберёт, а подменить ключи без кода не сможет. Тот, кто переберёт код потом по записи, узнает только публичные ключи и `did`.

## Обычный запрос

```
POST <адрес>/a1/<kid>/<spid>
тело  = b64url( eph_pub(32) ‖ AEAD(k_req, nonce 0, рамка, aad = "a1" ‖ kid ‖ eph_pub) )
k_req = HKDF(ikm = k_dev ‖ X25519(eph, S), salt = kid, info = "req" ‖ eph_pub)

ответ = b64url( S_eph(32) ‖ AEAD(k_res, nonce 0, рамка, aad = "a1r" ‖ kid ‖ eph_pub ‖ S_eph) )
k_res = HKDF(ikm = k_dev ‖ X25519(S_eph, eph_pub), salt = kid, info = "res" ‖ eph_pub)
```

Обязательные поля JSON запроса: `v` = 1, `t` — unix-время, `n` — 16 случайных байт в base64url, `op`. В ответе: `v`, `t`, `n` (эхо), `st` — настоящий код ответа, `sp` — текущий публичный ключ прослойки. Увидев новый `sp`, телефон пересчитывает `k_dev` и дальше ходит с новым отпечатком.

Снаружи ответ всегда `200`, `content-type: application/octet-stream`, `cache-control: no-store`.

Эфемерная пара прослойки — новая на каждый ответ, поэтому записанные ответы не вскрываются и после утечки `S` и `D`. Запросы такой защиты не имеют: `k_req` выводится из `k_dev` и `X25519(eph, S)`, и тот, у кого окажутся `S` (таблица `app_key`) и `dpub` телефона (таблица `app_dev`), прочитает записанные ранее запросы — в том числе `login` с паролем админки. Поэтому база прослойки и ключ `S` — такой же секрет, как сам пароль.

### Проверки на входе

Окно времени ±300 секунд; `n` принимается один раз и помнится 10 минут. Любая неудача — чужая метка, отключённый телефон, повтор, не расшифровалось, приложение выключено тумблером — запрос уходит в обычный конвейер и получает то же, что любой мусорный адрес. Своего ответа у отказа нет.

## Операции

| op | Нужен вход в админку | Запрос | Ответ |
|---|---|---|---|
| `hi` | нет | `name`, `os`, `osv`, `app` | `mw` версия прослойки, `api`, `apk` (`v`, `size`, `sha256` или `null`), `ev` виды событий, `wh` известные события вебхуков, `evw` предел ожидания |
| `login` | нет | `u`, `p` | `st` 200/401/429, `ck` — кука сессии админки `submw_admin=…` |
| `web` | кука | `m` метод, `p` путь, `h` заголовки, тело — тело запроса | `st`, `h` — список `[имя, значение]`, `auth` — жива ли сессия; тело — тело ответа |
| `ev` | нет | `c` курсор (−1 — начать с текущего), `w` сколько ждать, `k` нужные события | `c` новый курсор, `e` {событие: сколько}, `w` сколько ждали, `r` пауза перед следующим запросом, если мест для ожидания нет |
| `apk` | нет | — | тело — APK, `v`, `sha256` |
| `bye` | нет | — | телефон отключает себя сам |

Ключ телефона без пароля даёт только `hi`, `ev`, `apk` и `bye`: типы событий и файл приложения. Админка — только с живой сессией, то есть ключ телефона плюс пароль. Перебор пароля закрыт тем же замком, что вход в браузере (10 неудач за 15 минут по адресу), и отдельным — по телефону. Сессия из `login` помнит, какому телефону выдана: после отключения телефона она перестаёт действовать и в туннеле, и в браузере.

### Туннель админки (`web`)

Пускаются только `GET`, `POST`, `HEAD` и только `/admin/…`. Без живой сессии админки страницы не открываются: ответ сразу `401` с `auth: false`, форма входа в браузерном виде через канал недоступна. Статика `/admin/assets/…` отдаётся из файла с проверкой пути и `etag`; всё остальное — та же `admin/index.php`, что в браузере: метод, путь, заголовки, куки, формы и загрузки файлов встают на свои места, а ответ со всеми заголовками и кодом уходит обратно внутри шифра.

В приложении WebView ходит в локальный сервер на `127.0.0.1`, а тот заворачивает запросы в `web`. Куку сессии держит сам локальный сервер, в WebView она не попадает; внешние адреса WebView не открывает.

### Уведомления (`ev`)

Прослойка пишет в таблицу `app_ev` только вид события — без имён, адресов и текста — и хранит 7 суток:

| Ключ | Когда |
|---|---|
| `chat` | новое сообщение пользователя в чате поддержки |
| `rep` | новый отчёт Clod Clash — то же, что считает конверт в шапке админки |
| `chan_new` | новая подписка впервые пришла по защищённому каналу |
| `wh:<событие>` | вебхук панели (`wh:user.expired`, `wh:node.connection_lost`, …) |

В `k` можно передать маску с `*` в конце: `wh:*`, `wh:node.*`. Запрос `ev` держится до `w` секунд (не дольше `evw`), раз в 2 секунды смотрит новые записи и отвечает сразу, как пришло нужное. Новый запрос `ev` того же телефона закрывает прежний в пределах полусекунды — после смены сети на сервере не висят старые соединения.

Ждать одновременно могут не больше телефонов, чем задано на вкладке «Приложение» (по умолчанию 2): пул процессов PHP общий с подписками и каналом c1, и уведомления не должны его выедать. Место занимается блокировкой файла и освобождается, даже если процесс упал. Когда мест нет, `ev` отвечает сразу, без событий и без ожидания, с полем `r` — паузой в секундах (случайные 45–75, чтобы телефоны не приходили разом); приложение ждёт её и спрашивает снова. Если прежний запрос того же телефона ещё ждал, новый закрывает его и забирает освободившееся место (ждёт до 3 секунд), поэтому смена сети не переводит телефон на редкий опрос.

Пока соединение открыто, оно занимает процесс PHP. Если сервер или прокси рвут долгие запросы, приложение само укорачивает срок. Где поднять предел: Apache + mod_fcgid — `FcgidIOTimeout`, nginx — `fastcgi_read_timeout` (за прокси ещё `proxy_read_timeout`). Cloudflare рвёт ответ через 100 секунд. В Docker-образе прослойки `fastcgi_read_timeout 300s` уже стоит.

### APK

Раз в сутки, когда открывается админка — в браузере или в приложении, — прослойка в фоне смотрит последний релиз `submw-android`, скачивает APK в `data/app/` и отдаёт его телефону через `apk`. Запросы телефона этим не задерживаются. Скачать файл можно и на вкладке «Приложение». Файл берётся только по `https` с `github.com`, `api.github.com`, `objects.githubusercontent.com` и `release-assets.githubusercontent.com` — включая перенаправления, — и всегда с проверкой сертификата, независимо от настройки проверки TLS для панели.
